1.1: Constructing Noisy Training Inputs

Here's my implementation of the interpolate function, to create noisy images that can be used as inputs to our denoising models. This formulation ends up creating a straight line relationship between our image and random Gaussian noise. 

def interpolate(image, noise, t):
    return t * image + (1 - t) * noise

1.3: One-Step Denoising

Now, let's use our pretrained model to go from noise to a clean image in one prediction step. 

def one_step_denoise(x, t, condition, predict_velocity):
    with torch.no_grad():
      x1_hat = x + (1-t) * predict_velocity(x, t, condition)
      return x1_hat

As expected, at higher noises, our prediction is blurry and losing high frequency details. At lower noise levels, we mostly recover our image!

1.4: Visualizing Velocity

Now let's visualize how the predicted velocity from our model compares to the actual ground truth velocity. Again, at lower noise levels, we have less error and we're really just missing high frequency details.

1.5: Iterative Denoising with Euler Sampling

One step clearly doesn't work too great. Now let's use iterative Euler sampling to progressively denoise! Plotted below are the images after every fifth update, and comparisons to the old blurring and 1step methods.

@torch.inference_mode()
def euler_sample(x_start, t_start, step_size, velocity):
    states = [(t_start, x_start)]

    while t_start < 1:
      dt = min(step_size, 1 - t_start)
      x_start = x_start + dt*velocity(x_start, t_start)
      t_start = min(1, t_start + dt)
      states.append((t_start, x_start))


    return x_start, states

2. Conditional Generation and Guidance

2.1: Classifier-Free Guidance (CFG)

Now let's try implementing Classifier-Free Guidance to hopefully guide the model towards realistic images that still follow our prompt. Here, I'm using a weight of 7.

def cfg_velocity(x, t, condition, w, predict_velocity, null_condition=''):
    v_uncond = predict_velocity(x, t, null_condition)
    v_cond = predict_velocity(x, t, condition)

    return v_cond + w*(v_cond - v_uncond)

Much better, way more realistic, and way less creepy. CFG is cool!

3.3: Visual Anagrams

Visual anagrams are images that show something when viewed one way and something completely different when viewed upside down. We can use diffusion and flow models to create these by averaging CFG velocities on a right-side-up perspective and upside-down perspective of our images, pushing two models to balance their generations in this cool flip relationship. Here's my code and some examples: 

def visual_anagrams(noise, condition_a, condition_b, predict_velocity, w=7, step_size=0.02):
    def avg_v_helper(x, t):
      v1 = cfg_velocity(x, t, condition_a, w, predict_velocity)
      v2 = rotate180(cfg_velocity(rotate180(x), t, condition_b, w, predict_velocity))
      return 0.5 * (v1 + v2)
    return euler_sample(noise, 0.0, step_size, avg_v_helper)[0]

3.4: Hybrid Images

We've looked at Hybrid images before! These are images that show something when viewed from close up and something else when viewed from far away. We do this by keeping low frequencies of velocities to create the far away image, and high frequencies to create the details of the close up image. Adding these together leads to our multi-scale hybrid! 

def make_hybrids(noise, condition_a, condition_b, predict_velocity, w=7, step_size=0.02):
    def factorized_helper(x, t):
      v1 = lowpass(cfg_velocity(x, t, condition_a, w, predict_velocity))
      v2 = highpass(cfg_velocity(x, t, condition_b, w, predict_velocity))
      return (v1 + v2)
    return euler_sample(noise, 0.0, step_size, factorized_helper)[0]

Removing the learning rate scheduler

I was asked to remove the learning rate scheduler to see how this affected training. Fine. I first removed the scheduler while keeping the default learning rate of 1e-2. I then lowered the fixed learning rate to 1e-4. From my knowledge of schedulers, they anneal the learning rate over time, making gradient descent more stable and ensuring our model's parameters do not go far away from the minima we have been chasing. To counteract the effects of removing a scheduler, I decided that lowering the LR would help keep training stable, even if it slows down initial progress.
